# Atlas · 教学方法论（全站）

> 层级：**全局方法论**。回答"一模块怎么写"和"一本手册怎么组织"，跨课题通用。
> 视觉/工程见 [DESIGN-SYSTEM.md](DESIGN-SYSTEM.md)；课题专属参数见各课题 `TOPIC.md`；操作清单见 `/spec-patch.md`。

## 1. 三条设计原则

1. **痛点先行**——Part 1 永远是"朴素做法为什么会骗人"。认知冲突先于方法论。
2. **凡概念必有例子，凡例子必可复算**——数字全部给出、可手算验证；禁止只说"明显上升"。
3. **教学层与真实层分层**——教学示例（Chart.js + 教学脚注）与真实案例（静态图 + `tag-real`）分开呈现，并说清"真实世界比教程复杂在哪"。

## 2. 模块教学骨架

```
① 痛点（类比垫场）
② 核心概念（concept-grid，2~4 卡）
③ 图鉴/方法（怎么做）
④ 手算一遍（method-step + calc-box，数字全给）
⑤ 实战案例（case-step 流水）
⑥ 三个坑（pitfall）
⑦ 速查表（cheat-grid，一张卡一个"决策/指标"）
⑧ 自测（quiz-item）
（可选）真实数据 Part
收尾：summary-box + mnemonic-line 口诀 + next-card + 页脚
```

课题原型替换约束（见 §4）：帧不换，**核心 Part（手算/案例）按原型替换**。

## 3. 写作规范

- **语言**：口语化、第二人称、短句；允许比喻和情绪（"但这张图撒了谎"——这类句式的合法位置是一句号后立刻给精确表述）。
- **checklist**：动词开头、可检验（"能解释……"而不是"理解……"）。
- **类比**：只负责"直觉"，紧随其后就回到精确表述。每个课题有自己的类比池（放在该课题 `TOPIC.md`）。
- **口诀**：小结必须带 `mnemonic-line`。概念卡必须带 `c-mnemonic` 或记忆点——记忆锚点是内容的一部分。

**内容节奏**（隐性，最易写崩的四条）：

1. **电池式标题**：`图X1 · 对象：发现句`——冒号后那句脑补比图本身更能教会人。页面 h1 也必须是问题式/结论式而非描述式。
2. **阈值表原则**：每一组成组指标都必须配"`值 → 业务判断`"表——没有阈值表的指标 = 教学失败。
3. **反直觉**：每隔 2~3 个 Part 必须有一个"你以为 X，其实 Y"的强调，落在具体数字上。写完感觉通篇没打脸点 → 数据故事太平，要么不该写这个模块，要么知识密度不够。
4. **口语计数**：数字必须跟时间/量级/对比对象绑定（"上线时 vs 9 个月后""128 倍""0.02 → 0.179"）。

**自测题**：难度递进 = 概念辨析 → 定义复述 → 计算题（题干给足数字）→ 信号判读 → 分析题（开放排查）。答案藏在 `details` 里，关键结论在前加粗，做到能反推回对应 Part。

## 4. 课题原型（4 种）——开新课题第一件事是选型

| 原型 | 适用 | 核心 Part | 自测侧重 | 图表侧重 |
|---|---|---|---|---|
| 计算/模型型 | 信贷、量化、定价、归因 | 手算一遍（method-step + calc-box） | 计算题 | 曲线、分布、散点 |
| 制度/法规型 | 合规、监管框架、合同条款 | 条文拆解 + 情景判例（概念卡 + callout） | 情景判断题 | 流程图、对照表 |
| 流程/实务型 | 发行全流程、尽调、运维 | 流程演练 + 文档样例（case-step + method-step） | 排序、找错题 | 时间轴、泳道图 |
| 概念/框架型 | 宏观、行业研究、比较法 | 框架对比 + 案例套用（concept-grid 为主） | 辨析、迁移题 | 矩阵、因果图 |

**数量规则（区间 + 默认值）**：

| 项 | 区间 | 默认 | 校验器约束 |
|---|---|---|---|
| 坑 | 2~4 | 3 | = 3（做宽改进中） |
| 自测 | 4~7 | 5（≥1 迁移题） | = 5 |
| 速查卡 | 6~10 | 8~9 | 8~9 |
| 模块数 | 4~10 | 5~7 | — |
| 主线 | ≥1 | 2 条正交 | — |

校验器当前的硬规则（3/5/8~9）是对计算型默认值的执行；法规/流程/概念型课题在 `topic.json` 里声明原型后，校验器按原型区间判定（演进方向）。

## 5. 跨模块叙事线（最重要的内容设计）

至少找到 1 个贯穿整个知识体系的"元案例"：一个特征/一份数据/一批数字，被多个模块反复引用、反复重算。没有这条线，N 个模块就是 N 篇孤立文章，不是一本手册。

- 权威值落进该课题的 `narrative.json`（数值 + 锚定词 + scope）。
- 原始数据落进该课题的 `data/`（CSV），供读者亲手复算，同时是登记表的生成来源。
- 每个新模块写完，按 `/spec-patch.md` 走一遍。

## 6. 学习效果层（会越用越差的方向）

- 自测：建议"先写后看"——`<summary>` 提示把答案写在纸上再展开；答案末尾加"↩ 回看 Part N"锚点。
- 读起来 ≠ 记住：`review.html`（跨模块综合题 / 口诀汇总 / Anki 导出）作为复习层。
- 工作映射：`reports/` 作为课题输出区——学习日志、与工作边界的映射。
- 延伸阅读：参考教材章节 / 监管文件 / 实务来源（防止单点深度锚点）。
