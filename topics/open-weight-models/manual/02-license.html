01

痛点 · DeepSeek、Qwen、Kimi K3 与 Llama 的许可证红线在哪？

文件拿到了不等于可以任意商用：许可证把竞争线画在哪里

下载一份可运行的模型权重，仍要看版本对应的许可证。按当时所见比较 DeepSeek V3/R1 的 MIT、部分 Qwen 产品的 Apache 2.0、智谱自 GLM-4-0414 起部分版本的 MIT、Kimi K3 的专有条款与 Llama Community License。这里不能把某一家公司的全部历史和未来模型写成同一许可：授权看精确版本、发布仓库、使用日期，还要看权重、代码与工具是否分别持有不同协议。

Kimi K3 所述的协议中，产品达到约 1 亿月活或每月 2000 万美元收入门槛时，有显著标识要求；模型托管服务达到连续 12 个月一定收入门槛时，可能需要另签商用协议。它与条款更宽的 MIT 不同，也与“人人须交许可费”不同。Llama 社区协议中也有 7 亿月活额外授权门槛、部分用途限制，以及 Meta 某新模型转向 Apache 2.0，说明同一厂商内部也会改变策略。以上门槛及适用范围尚需逐条对照许可证；投入生产前要读原始许可证，而非凭这段摘要判断合规。

放宽许可有两面：免费给个人和企业开发者用，可以扩大采用；但若托管平台原封不动包装成 API 收费，模型厂商可能希望分到收益。许可条款既是开发者成本，也是争取分发和商业谈判的工具。

02

关键事实与判断边界

把事件、数字和判断分开，才不会让不同主体的账混在一起。

把还涉及的具体门槛保留下来

DeepSeek V3/R1；部分 Qwen/GLM

待核协议与门槛
分别提及 MIT、Apache 2.0、MIT；通常允许修改和商用但附署名/版权等义务
部署前必须做什么
核权重、代码和衍生发布分别适用何种许可证

Kimi K3 自定义许可

待核协议与门槛
据称月活超 1 亿或月收入超 2000 万美元触发显著标识；托管 MaaS 连续 12 个月收入超 2000 万美元需另谈协议
部署前必须做什么
按相应 revision 的 LICENSE 核门槛、主体和定义；口述绝非合同解释

Meta Llama 部分版本

待核协议与门槛
提 7 亿月活门槛及限制用模型输出训练竞争模型
部署前必须做什么
各代许可与附加可接受使用政策逐条看，不能把限制挪给新版

据称 Meta Muse Glimmer

待核协议与门槛
据称某 300 亿参数模型改用 Apache 2.0
部署前必须做什么
先核型号是否存在、仓库与许可；不因一句新闻更改 Llama 许可证认知

为什么要把模型家族和每个仓库分开

还存在“Meta 新发布 Muse Glimmer 使用 Apache 2.0、Muse Spark 后续可能开放权重”的消息。即使查证属实，也只是这些型号的发布选择，不会自动修改 Llama 1—4 的历史许可；同理“Qwen 改用 Apache 2.0”不能覆盖它的所有旗舰/闭源版本。要复制模型商业部署，记录仓库地址、commit、模型卡日期、权重许可证、配套代码许可证及附加使用政策。

授权范围
按版本看使用、复制、修改、分发、托管、标识义务。
条文是门
开放标准
某许可证的商用限制可能使其不符合OSI的开放AI定义。
“开放”有定义

MIT和Apache 2.0的合规条件也不等于“什么都不用做”；现实模型可有自定义协议及附加政策。

03

三个容易踩的坑

坑一 · 免费=无限商用
免费获取与使用范围是两码事。
坑二 · 代码许可=权重许可
文件对象需分开审。
坑三 · 猜另一版本相同
新版本可能改变限制和命名。

本节小结

模型可下载不意味着可无限制再发布、托管或商用；DeepSeek、Qwen、GLM、Kimi 和 Llama 的条款须按具体版本核读。
