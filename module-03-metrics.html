01

先说痛点：为什么不能用"准确率"

这是整个模块的出发点。风控建模第一课，往往不是学怎么调模型，而是学怎么正确地评价一个模型。

🎯 一个类比 假设一个靶场里，100 箭只有 5 箭是"该打中的靶心"（坏客户），95 箭是"不用管的空靶"（好客户）。有个"选手"从来不瞄准，无论什么情况都喊"这是空靶"——结果他 95% 的判断都对，"准确率"高达 95%。但他对唯一重要的事情（找出靶心）**一次都没做到**。信贷坏账客户往往只占总样本的 2%~10%，这就是典型的类别不平衡问题：不管坏样本，闭着眼睛全猜"好"，准确率照样很高，但模型毫无业务价值。

风控真正关心的问题不是"猜没猜对"，而是：

业务问题该用的指标
模型能不能把好客户和坏客户排序区分开？KS、AUC
模型上线之后，还准不准，是不是在悄悄失效？PSI
只批最高风险的一批人不放款，能拦住多少坏账？Lift / Gini
准确率错在哪 准确率把"猜对"和"猜错"一视同仁地计数，但风控场景里，漏掉一个真坏客户的代价，远大于误判一个好客户（前者是实打实的坏账损失，后者只是少赚一笔利息）。评估指标必须能体现这种不对称，这正是 KS、AUC 这类"排序类"指标的设计出发点——它们看的是模型有没有本事把坏客户尽量排在"高风险"这一端，而不是简单的对错计数。
02

两个必须先搞清楚的概念

后面所有指标的计算，都建立在这两件事之上。

好坏客户定义
Good / Bad Definition
在一个固定的观察窗口内（比如放款后6个月），逾期超过某个天数（如30天）就标记为"坏"，否则为"好"。这个定义一旦定下来，全流程都要用同一个口径，不能中途改。
记忆点：先定义清楚"什么算坏"，指标才有意义
评分 / 预测概率
Score / Predicted Probability
模型对每个客户打出的一个分数，代表"有多大可能是坏客户"。约定好方向：本节统一按分数越低风险越高（评分卡习惯），排序类指标全部建立在"按分数排个序"这个动作上。
记忆点：先排序，好坏指标才能算

样本要怎么切分——这也是后面 PSI 章节"基准 vs 现状"对比的前提：

训练集用来拟合模型
验证集用来调参
测试集模拟"未来"
上线建模时的基准
月度监控PSI登场
跨时间验证比随机切分更严格 测试集最好是建模用的时间之后的一段新数据（Out-of-Time），而不是简单从同一批数据里随机切一部分（Out-of-Sample）。后者容易高估模型效果——毕竟随机切分的测试集和训练集来自"同一个时间点的客群"，遇不到真实世界里客群随时间漂移的问题，而这恰恰是模型上线后最先失效的地方（见第⑥节 PSI）。
03

指标图鉴：4 个最常用的模型评估指标

分成两组：KS、AUC、Gini 回答"模型准不准"；PSI 回答"模型还稳不稳"。

① KS（区分度）
Kolmogorov-Smirnov
模型把好客户和坏客户拉开的最大距离。按分数排序后，累计坏客户占比曲线和累计好客户占比曲线之间，垂直方向最大的差值。
KS = max( 累计坏% − 累计好% )
贷前A卡：>0.3较好；互联网小额贷0.25~0.35已属不易
② AUC（整体排序能力）
Area Under the ROC Curve
ROC曲线下的面积，衡量模型在所有可能阈值下的排序能力。随机模型AUC=0.5，完美模型=1。
AUC = ROC曲线下面积
业内经验：0.8以上可考虑投产
③ Gini系数
Gini Coefficient
跟AUC是同一枚硬币的两面，衡量排序不平等程度，两者可以互相换算。
Gini = 2×AUC − 1
AUC=0.79 → Gini=0.58
④ PSI（稳定性）
Population Stability Index
对比"建模时的分布"和"当前的分布"，衡量客群或评分分布有没有漂移。跟准不准无关，只看稳不稳。
PSI = Σ(实际占比−预期占比)×ln(实际占比/预期占比)
<0.1稳定；0.1~0.25关注；>0.25必须排查

05

ROC 曲线怎么读，AUC 怎么算

用第④节完全同一份十分位数据，换一种画法。

💡 KS 和 AUC 的关系 KS 曲线的两条线，其实就是 ROC 曲线的原材料——把"累计好%"当横轴（FPR，误伤率），"累计坏%"当纵轴（TPR，抓获率），逐个十分位描点连线，就是 ROC 曲线。KS 看的是两条线之间"某一点"的最大垂直距离，AUC 看的是曲线下面"整片"的面积——KS 关心最强的那个分割点，AUC 关心全局的排序能力，两者经常同向变化，但衡量的东西不完全一样。
图K2 · ROC 曲线
曲线越往左上角"鼓"，模型越好；对角虚线是"随机瞎猜"模型的基准线
示例数据，用于教学演示，非真实业务数据。
用梯形法对10个十分位的点逐段积分，求ROC曲线下面积：
AUC ≈ 0.79　（对应 Gini = 2×0.79−1 = 0.58）
AUC 区间业务判断
< 0.6基本没有区分能力，别用
0.6 ~ 0.7较弱，可作辅助特征但别独立上线
0.7 ~ 0.8可用，互联网小额贷常见水平
0.8 以上业内经验上可以考虑投产
KS 和 AUC 出现矛盾时怎么看 有时会遇到 AUC 中等但 KS 很高的模型：说明模型在某个特定分数区间区分能力极强，但整体排序一般。如果业务上就是要找一个明确的"一刀切"拒绝点，高 KS 更有用；如果业务上是要给全体客户排出精细的风险序列（比如分层定价），AUC 更能代表整体表现。两个指标要一起看，别只报一个数字。
06

PSI：模型上线后的"体检指标"

KS、AUC 回答"模型准不准"，但一个模型上线时准，半年后可能因为客群变了而悄悄失效——这就要靠 PSI 来盯着。

👕 一个类比 PSI 就像"这件衣服还合不合身"。模型是照着建模时的客群"量体裁衣"的，如果半年后来申请的客群结构变了（比如某个新渠道大量导流进来一批完全不同的人），这件"衣服"哪怕本身没坏，穿在新客群身上也会不合适。PSI 不管衣服本身好不好，只管"人变了没有"。

用评分区间分布做一次真实计算——对比"建模时的基准分布"和"上线9个月后的当前分布"：

评分区间建模时占比(预期)9个月后占比(实际)该箱PSI贡献
[300,500) 高风险10%22%0.0946
[500,580)20%25%0.0112
[580,650)30%27%0.0032
[650,720)25%14%0.0638
[720,850] 低风险15%12%0.0067
PSI 总计0.179
单箱PSI贡献 = (实际占比−预期占比) × ln(实际占比/预期占比)
以第一箱为例：= (0.22−0.10) × ln(0.22/0.10) = 0.12 × 0.788 ≈ 0.0946
PSI总计 = 各箱贡献相加 = 0.0946+0.0112+0.0032+0.0638+0.0067 ≈ 0.179

柱子差得越多，那个分数段的PSI贡献就越大
示例数据，用于教学演示，非真实业务数据。
PSI=0.179，已经进入"需要关注"区间 最高风险分段 [300,500) 的客户占比从 10% 涨到 22%，几乎翻倍，单这一箱就贡献了总PSI的一半以上（0.0946/0.179≈53%）——这是判断"漂移发生在哪里"的关键动作：不能只看总PSI一个数字，要拆到分箱才知道问题出在客群的哪一段。这个发现会在第⑦节案例里被进一步追查。
PSI 区间业务判断
< 0.1稳定，正常监控
0.1 ~ 0.25有一定漂移，需要排查原因
> 0.25严重漂移，模型很可能已经不适用，考虑重新建模
评分PSI 和 特征PSI，要两层都监控 这里算的是评分PSI（模型最终输出的分数分布有没有变）。但还应该对每一个入模特征单独算PSI——因为多个特征可能往不同方向漂移，互相抵消，导致评分PSI看起来还行，但某个关键特征早就大幅漂移了。第⑦节案例会具体走一遍这个排查过程。

实战案例：从上线达标到触发模型迭代

把前面三节的指标串成一个模型全生命周期的监控故事。

1

上线时基线达标

模型上线（T0）时验证指标：KS=0.46，AUC=0.79，均达到内部投产标准，正式切流上线。

月度监控例行检查，发现指标在缓慢下滑

上线9个月后，KS 降到 0.38，AUC 降到 0.74，PSI 从上线初期的 0.02 爬升到 0.179（图K4）。→ 三项都触发了预警阈值：KS降幅(0.46→0.38)达17.4%（阈值10%）、AUC降幅6.3%（阈值5%）、PSI 0.179（阈值0.1），一致指向"模型在衰退"。

拆分箱定位漂移发生在哪里

评分分布对比显示，最高风险分段 [300,500) 客户占比从10%涨到22%（第⑥节图K3）。→ 说明流入了大量高风险客户，不是随机噪音。

下钻到入模特征层，找到具体原因

先解释两个词。入模特征，就是最终喂进逻辑回归、参与算分的那几个变量——比如这张卡用的是年龄、婚姻状况、学历、历史逾期次数、月收入、近3个月申请次数这6个（第⑥节的分箱得分表就是它们转换出来的结果）。评分是这6个特征的WOE分别乘以各自的回归系数、再加总换算出来的一个数。

🍲 一个类比 评分PSI就像"这锅汤走没走味"，但汤是6种食材熬出来的——汤走味了，不代表每种食材都变了，可能只是其中一种食材本身不新鲜。特征PSI就是把食材一样一样挑出来单独检查：对每一个入模特征，分别拿"建模时这个特征的分布"和"现在这个特征的分布"做对比，用第⑥节一模一样的PSI公式单独算一遍——只是这次不对着最终评分算，对着某一个特征自己的取值分箱算。

第一步：给6个入模特征各自算一遍PSI，排出来看：

入模特征该特征自身的PSI判断
学历0.01稳定
婚姻状况0.03稳定
年龄0.02稳定
月收入0.04稳定
历史逾期次数0.05稳定
近3个月申请次数0.19严重漂移，明显异常
图K5 · 6个入模特征各自的PSI排行
5个特征都很稳定，只有一个特征的PSI远超其他——它就是嫌疑对象
示例数据，用于教学演示，非真实业务数据。

6个特征里5个都稳定在0.05以下，只有"近3个月申请次数"一个特征PSI=0.19，一下子就跳出来了——这就是"逐个检查"定位到具体特征的过程：不是靠猜，是把每个特征都单独算一遍PSI，再排序，异常值自己会露出来。

第二步：把这一个特征拆到它自己的分箱，看漂移具体发生在哪一段——跟第⑥节对评分做的事情一样，只是这次拆的是"近3个月申请次数"自己的5个分箱（跟模块二算WOE用的是同一套分箱）：

定位到了：高值段占比几乎翻倍 "6次以上"这个高值段（[6,8]次+[9,+)次两箱合计）的占比，从建模时的 10.3%+5.8%=16.1%，涨到现在的 17%+15%=32%——几乎翻了一倍。而这个高值段在模块二里正是WOE最高（最risky）的那一段。→ 结合业务背景排查，判断是某个新引流渠道带来了大量"多头申请"客群，这类客群本身的申请行为特征跟建模时的主力客群系统性不同。
串起来看这三步下钻 评分PSI(0.179，第⑥节) 告诉你"整体在变差" → 特征PSI排行(图K5) 告诉你"是这一个特征在变差，不是别的" → 该特征自己的分箱分布(图K6) 告诉你"具体是它的哪一段客群变多了"。每一步都是同一个PSI公式，只是拿去对比的"分布"从"评分"换成"某个特征"、再换成"该特征的某一段"，颗粒度一层层变细，问题也就一层层被锁定。

决策与行动

  • 短期：对"近3个月申请次数"高值段客户临时加严准入规则，止住风险敞口扩大
  • 中期：启动模型迭代，把新渠道客群纳入训练样本重新建模，或对新老客群分别建模
  • 用冠军/挑战者框架小流量测试新模型，比较新老模型的KS/AUC/坏账率，确认新模型显著优于老模型后再切全量
  • 复盘引流渠道的准入口径，评估是否要在渠道侧就做拦截，而不是全部指望模型兜底
08

三个容易踩的坑

坑一 · 训练集指标漂亮，测试集大幅跳水
比如 KS_训练集=0.58，KS_测试集=0.35——差距接近40%，这是典型的过拟合信号：模型在训练数据上学到了噪音而不是真实规律。验证报告永远要同时报训练集和测试集（最好是跨时间的测试集）的指标，只看训练集的漂亮数字毫无意义。
坑二 · 极端样本不平衡下，指标会"看起来还行"但没业务价值
当坏样本占比极低（比如<1%）时，个别指标可能因为多数类主导计算而显得"过得去"，但模型实际可能毫无区分力。务必配合分箱后坏账率是否单调递减、KS曲线形状是否合理一起判断，不能只看一个汇总数字。
坑三 · 只监控评分总PSI，不监控入模特征PSI
评分是多个特征加权算出来的，多个特征可能朝相反方向漂移、互相抵消，导致评分PSI看起来平稳，但某个关键特征早就大幅偏移，业务风险已经在积累。第⑦节案例正是靠"评分PSI预警→拆分箱→下钻到特征PSI"这条链路才找到真实原因——评分层的监控不能替代特征层的监控。

自测：检验一下是不是真的懂了

Q1. 一个模型准确率98%，为什么风控团队还是拒绝上线？
查看解析
因为坏客户占比本来就可能只有2%左右，一个永远预测"好客户"的模型什么都没学到，准确率也能到98%。风控评估要用能体现"排序能力"的指标（KS/AUC），不能用准确率。
Q2. KS曲线的两条线分别代表什么？KS怎么算出来？
查看解析
一条是"累计坏客户占比"（按分数从高风险到低风险排序后，抓到的坏客户比例），一条是"累计好客户占比"（同样排序下误伤的好客户比例）。KS = 两条线之间垂直方向的最大差值。
Q3. 计算题：某分数段建模时占比15%，当前占比8%，这一箱对PSI的贡献是多少？（提示：ln(8/15)≈−0.629）
查看解析
该箱贡献 = (0.08−0.15) × ln(0.08/0.15) = (−0.07) × (−0.629) ≈ 0.044。注意实际占比下降时，(实际−预期)是负数，ln(实际/预期)也是负数，两个负数相乘还是正的——PSI的每一箱贡献恒为非负值。
Q4. KS_训练集=0.55，KS_测试集=0.33，这说明什么问题？
查看解析
典型的过拟合信号——模型在训练集上表现远好于测试集，说明它学到的是训练数据里的噪音/偶然规律，而不是能泛化的真实规律，直接上线大概率在真实业务上达不到训练集展示的效果。
Q5. 分析题：评分PSI只有0.06（很稳定），但业务反馈坏账率在悄悄上升，可能是什么原因？该怎么排查？
查看解析
很可能是某几个入模特征朝相反方向漂移，在评分层互相抵消了，导致最终评分分布看起来没变，但客群结构其实已经变化。应对：逐个检查入模特征的PSI（而不是只看评分总PSI），找到具体是哪个特征在漂移，再结合业务判断根因（新渠道、新产品、宏观环境变化等）。

本节小结

模型评估要分两层看：KS/AUC 回答"模型准不准"（上线前的门槛），PSI 回答"模型还稳不稳"（上线后的体检）。两层都要有，且都要拆到"分箱/分特征"这个颗粒度去看，不能只报一个汇总数字——汇总数字能让你知道"要不要担心"，拆开的分箱才能告诉你"问题出在哪"。

上线前看排序力，上线后看稳定性，出问题永远往细处拆。
